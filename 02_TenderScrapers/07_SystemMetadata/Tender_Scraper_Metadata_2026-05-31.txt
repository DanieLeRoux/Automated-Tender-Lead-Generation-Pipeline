Purpose
-------
The TenderScrapers system monitors multiple tender portals, extracts current tender opportunities, standardises source-specific data into a common structure, applies a central scoring model, deduplicates repeated opportunities across sources, filters out low-relevance tenders from the bid-manager daily review, and produces consolidated daily review workbooks for bid screening.

The system is intended as a tender discovery, prioritisation and monitoring tool. It does not replace bid/no-bid judgement.

Core Design
-----------
The system is split into two levels:

1. Source-level scrapers
   - Each source scraper collects data from one tender portal.
   - Each scraper produces raw, master, delta, updates and top-delta outputs for that source.
   - Source outputs remain useful for audit, debugging and troubleshooting.

2. Central consolidation layer
   - Consolidates all source outputs into a standard schema.
   - Recalculates current status centrally.
   - Applies one standard scoring model across all sources.
   - Applies review-eligibility filtering for the daily review.
   - Deduplicates tenders where the same opportunity appears across more than one portal.
   - Performs robust date parsing, including Excel serial dates.
   - Produces consolidated master, delta, updates, top-delta and daily review workbooks.

Reporting Tabs
--------------
By Source
    Shows all configured/enabled scraper sources and operational row counts, including sources that produced zero daily-review rows.

Source Coverage
    Shows sources represented in the current bid-manager review list. A source not appearing here does not necessarily mean it failed; it may have had no current/review-eligible tenders.

Scraper Run Summary
    Operational summary showing all configured sources and source-level row counts. This tab helps distinguish scraper execution status from bid-review relevance.

Field Display Logic
-------------------
tender_reference
    Consolidated display field using tender_number first, then reference_number, then opportunity_key.

location
    Uses province first, then country_name, then region. For South African sources, province is used where available. If province is available, country should be treated as South Africa conceptually.

closing_date_time
    Uses the aligned closing datetime field. This avoids showing both closing_date and closing_datetime separately in the daily review.

action_url
    The best available link for the bid manager to use. This may be:
    - a direct document/download link;
    - a tender detail page;
    - a source portal page; or
    - the eTenders portal for manual lookup.

document_access_status
    Indicates how the tender information can be accessed. Typical values include:
    - Direct document available
    - Source/detail page only
    - Manual eTenders lookup required

eTenders Treatment
------------------
eTenders is treated as a discovery feed with document-link enrichment where possible.

The eTenders API/listing response includes supportDocument metadata for many opportunities. Where supportDocument data is available, the scraper constructs direct download URLs using the pattern:

https://www.etenders.gov.za/home/Download/?blobName=<supportDocumentID><extension>&downloadedFileName=<URL-encoded fileName>

For eTenders opportunities with supportDocument records:
    document_access_status = Direct document available
    action_url = first available eTenders document download link

For eTenders opportunities without usable supportDocument records:
    document_access_status = Manual eTenders lookup required
    action_url = https://www.etenders.gov.za/Home/opportunities?id=1

Where an eTenders opportunity is deduplicated with another entity source that provides a better detail/document link, the consolidated action_url should prefer the non-eTenders source link where appropriate.

Current Status and Date Logic
-----------------------------
The consolidation layer recalculates is_current centrally. It should not rely only on source-level is_current flags.

General rule:
    is_current = TRUE if closing_datetime is today/future.
    If closing_datetime is missing but closing_date exists, closing_datetime is backfilled from closing_date.
    If closing_datetime exists, closing_date is aligned to the date part of closing_datetime.

Excel Serial Date Handling:
    The central date parser supports Excel serial date values from source Excel files.
    Example: 46191.4166666667 = 2026-06-18 10:00.
    This fix prevents valid eTenders dates from being lost during consolidation.

Duplicate Date Handling:
    Where duplicated opportunities appear across multiple sources, the consolidation layer should keep the best available valid closing date.
    If multiple valid dates exist, the earliest future date should generally be used.
    Only unresolved records with no reliable date should appear in Needs Manual Date Check.

Priority review tabs should only include current tenders with reliable closing dates, except for the separate Needs Manual Date Check tab.

Manual Date Check Logic
-----------------------
Records without reliable closing dates are excluded from the main priority tabs and placed in:

Needs Manual Date Check

This tab is useful for review but should not drive daily priority screening until the closing date is confirmed. Current filtering rules also apply to this tab, so excluded low-relevance records should not appear there.

After Excel Serial Date Hotfix v21, eTenders-derived records should generally not appear in Needs Manual Date Check merely because of date-format issues.

Central Scoring Model
---------------------
The system recalculates the score centrally during consolidation. Source-specific original scores are not used for final prioritisation in the daily review.

Current score weights:

priority_client_match = 10
strategic_sector_keyword = 5
technical_keyword = 4
service_keyword = 4
procurement_delivery_keyword = 3
notice_type_match = 2
closing_soon = 2
has_documents = 1
has_contact_email = 1

Score Bands
-----------
20+     Very High Priority
12-19   High Priority
6-11    Medium Priority
1-5     Low Priority
0       No Match

Note:
The daily review focuses on Very High, High, Medium, Closing Soon, New Today, Updated Today and Manual Date Check tabs. Low/No Match records are retained in the fuller consolidated outputs where applicable.

Scoring Purpose
---------------
The score is a triage tool. It helps the bid manager review the most relevant opportunities first.

The score does not make the bid/no-bid decision. Final assessment still requires bid judgement, including:
- scope fit;
- eligibility;
- capacity;
- location;
- risk;
- commercial attractiveness;
- time to close;
- strategic value.

Review-Eligibility Filtering
----------------------------
The system applies review-eligibility filtering to reduce irrelevant tenders in the bid-manager daily review.

Filtering produces the following fields in the consolidated master/delta/updates outputs:

review_eligible
excluded_by_filter
exclusion_reason
excluded_keyword_matches

Excluded records remain in:
    consolidated_master.xlsx

Excluded records are removed from:
    consolidated_daily_review.xlsx
    consolidated_top_delta.xlsx

The filtering is intended to remove operational, administrative, HR, legal, ICT, supply-only and non-core tenders from the daily bid-manager shortlist.

Deduplication
-------------
The consolidation process attempts to identify duplicated opportunities across sources.

Example:
A tender appearing on both eTenders and DBSA should be consolidated into one record where matching logic identifies them as the same opportunity.

The system retains:
- source
- source_list
- action_url
- document_access_status
- duplicate-related fields in the master/audit outputs

For duplicated rows, field-level coalescing should preserve the best available source data, especially:
- closing_datetime
- action_url
- document_urls
- document_names
- province
- country_name
- contact_email

Power BI Recommendation
-----------------------
Power BI should preferably connect to:

consolidated_master.xlsx

rather than consolidated_daily_review.xlsx.

The daily review workbook is presentation-oriented and operational. The master workbook is a fuller dataset and is better suited for Power BI modelling.

Power BI should be refreshed after the scraper run has completed, not at the same time as the scraper is writing files.

Recommended timing:
    08:00 scraper run
    08:30 Power BI refresh
    08:45 daily email / review

Known Limitations
-----------------
1. Some eTenders items may still require manual lookup if supportDocument metadata is missing.
2. Some source websites can change layout, which may break individual scrapers.
3. Sibanye-Stillwater blocks automated access and is excluded.
4. COGTA has been disabled due to low-quality, noisy and slow scraping behaviour.
5. Some sources such as NamWater, City of Mbombela and City of Polokwane may not reliably expose closing dates on their own pages. Central consolidation may resolve duplicates from eTenders where available.
6. The system prioritises based on keyword, client/source and scope logic. It does not evaluate eligibility or commercial feasibility.
7. Source-specific portals may require login or manual lookup for full tender documentation.
8. Filtering is intentionally conservative but should be refined based on bid-manager feedback to avoid over-filtering useful opportunities.

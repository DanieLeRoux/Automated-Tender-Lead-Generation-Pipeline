------------
uMngeni-uThukela Water Tender Scraper

Script File
-----------
umngeni_uthukela_tender_pull_and_clean.py

Source Website
--------------
https://www.umngeni-uthukela.co.za/tender/

Source Type
-----------
Public HTML tender page / tender archive page.

Purpose
-------
The scraper monitors advertised tenders from uMngeni-uThukela Water, extracts tender information from the public tender page, stores raw and cleaned outputs, identifies new tenders, identifies updated tenders, and produces a top-delta shortlist based on weighted relevance scoring.

Filtering Logic
---------------
The raw outputs are kept unfiltered for audit and debugging.

The cleaned operational outputs apply the following default filtering:
- Keep only tenders where closing_datetime is greater than or equal to the current run date/time.
- Exclude archived tenders.
- Exclude cancelled or withdrawn notices.
- Exclude rows without a usable tender identifier where no reliable opportunity key can be constructed.

Optional command-line switches may override some of the default filtering:
--include-expired
--include-archived
--include-cancellations

Deduplication Logic
-------------------
The scraper uses opportunity_key as the unique identifier.

Where a reference number is available, it is used to build the opportunity key.
Where a reference number is not available, the scraper falls back to a stable combination of available fields such as description, closing date, and source URL.

Update Detection
----------------
The scraper calculates a row hash over key operational fields.

Typical fields used for update detection include:
- description
- issue_date
- closing_date
- closing_datetime
- status
- view_url
- document_names
- document_urls
- archived_flag
- cancellation_flag

If an existing opportunity_key has a different row hash from the previous master record, the tender is written to the updates file.

Delta Logic
-----------
A tender is written to the delta file when its opportunity_key does not already exist in the master file from a previous run.

Top Delta Logic
---------------
The top-delta file is created from the delta file only.

Rows are sorted by:
1. weight_score descending
2. closing_datetime ascending
3. issue_date ascending, where available

Default Behaviour
-----------------
The scraper creates all expected output files even where no qualifying rows are found.

Scoring Logic
-------------
The scraper applies weighted scoring to help prioritise tenders for review.

The score is based primarily on relevant words or phrases in the tender title/description, notice type, and source relevance.

Typical keyword categories include:
- Water
- Sanitation
- Engineering
- Civil Engineering
- Structural Engineering
- Mechanical
- Electrical
- HVAC
- Wet Services
- Design
- Refurbishment
- Maintenance
- Project Management
- Programme Management
- Feasibility Study
- Advisory Services
- Construction
- Infrastructure

The scoring should be reviewed and standardised later across all tender scrapers before creating the consolidated tender register.

Notes and Limitations
---------------------
The scraper depends on the current structure of the public uMngeni-uThukela Water tender page. If the website layout changes, the parser may need to be updated.

The scraper does not log into any private supplier portal and does not submit or download restricted tender information.

Document links are captured where available from the public page/detail pages.

The scraper should be reviewed after several live runs to confirm that:
- all active tenders are being captured;
- archived items are properly excluded;
- closing dates are parsed correctly;
- document links remain valid;
- scoring produces useful prioritisation.

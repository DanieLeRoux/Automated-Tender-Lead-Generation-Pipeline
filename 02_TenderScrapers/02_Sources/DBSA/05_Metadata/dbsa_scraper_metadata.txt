DBSA PROCUREMENT SCRAPER METADATA

Scraper name:
DBSA Procurement Scraper

Current script version:
dbsa_procurement_pull_and_clean_v2.py

Purpose:
Scrapes current procurement opportunities from the Development Bank of Southern Africa (DBSA) procurement webpage, cleans and structures the data, detects new and updated opportunities, and produces daily Excel outputs for review.

Source website:
https://www.dbsa.org/procurement

Scraper type:
HTML page scraper

Reason for scraper type:
DBSA does not appear to expose a clean public procurement API on the public procurement page. The scraper therefore reads the public HTML page, extracts visible procurement notice blocks, and captures associated document links where available.

Optional arguments:

    Includes tenders where the closing date has already passed.

    Includes notices identified as cancellation notices.

    Sets the minimum weight_score required for inclusion in the top-delta output.

Typical unique key basis:
DBSA source prefix plus tender/reference number where available.

Default filtering:
1. Excludes cancellation notices.
2. Excludes expired tenders.
3. Keeps general notices only where they have a valid future closing date.
4. Raw outputs remain broader for debugging; operational outputs are filtered.

Change detection:
The scraper calculates a row_hash using key operational fields. If an opportunity already exists in the master file but the row_hash changes, the opportunity is written to the updates file.

Typical fields used for update detection:
description
document_names
document_urls
briefing_session_details
date_published
closing_date
closing_datetime
cancellation_flag
general_notice_flag

Scoring logic:
The scraper applies a weight_score to support prioritisation of daily review items.

Scoring components:
1. Priority/client relevance component, where applicable.
2. Description keyword match count.
3. Each matched keyword increases the score.
4. Higher weight_score records appear higher in delta and top-delta outputs.

Excel formatting:
Each operational Excel output is written with headers, frozen top row, and an Excel table where rows exist. Empty outputs are still created so the user can confirm the script ran successfully even where no rows qualify.

Raw-vs-clean principle:
Raw files are retained to preserve the source scrape and assist with debugging.
Master, delta, updates, and top-delta are the operational files used for monitoring and review.

Known limitations:
1. The scraper depends on the public DBSA webpage structure.
2. DBSA may alter its HTML layout, which may require parser updates.
3. Some additional detail may exist inside downloadable tender documents, but the scraper currently captures the document links rather than parsing every document.
4. PDF/document enrichment should only be added later if the visible page data is insufficient.

Recommended review workflow:
1. Run scraper daily.
2. Review dbsa_top_delta.xlsx first.
3. Review dbsa_delta.xlsx for all new opportunities.
4. Review dbsa_updates.xlsx for changed opportunities.
5. Use document_urls to open official DBSA tender documentation.

Recommended future improvements:
1. Add optional document/PDF enrichment for top-scoring tenders.
2. Add consolidated cross-source tender register.

4. Add Power Automate integration for the delta and top-delta files.
5. Add alerting for high-score opportunities.

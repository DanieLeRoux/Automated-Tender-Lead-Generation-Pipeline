eTenders Scraper Metadata
==========================

Script Name
-----------
etenders_pull_and_clean_weighted_v2.py

Purpose
-------
Fetch currently advertised tenders from the South African eTenders API, clean and normalise the data, filter the clean outputs to professional services opportunities, apply a priority weight score, and maintain daily Excel outputs for master tracking, new tenders, changed tenders, and top-scoring new tenders.

Source Portal
-------------
South African eTenders Portal

Base Page
---------
https://www.etenders.gov.za/Home/opportunities?id=1

API Endpoint
------------
https://www.etenders.gov.za/Home/PaginatedTenderOpportunities

Primary Use Case
----------------
Daily tender monitoring for relevant professional services opportunities, with weighted prioritisation for Henry Fagan review.

Output Files
------------
1. etenders_active_raw.csv
   - Raw API output saved as CSV.
   - Unfiltered.
   - Used for audit/debugging.

2. etenders_active_raw_full.xlsx
   - Raw API output saved as Excel.
   - Unfiltered.
   - Used for audit/debugging.

3. etenders_master.xlsx
   - Latest clean snapshot of tenders within the target category.
   - Deduplicated by bid_number.
   - Incoming rows win during deduplication to backfill new or updated fields.

4. etenders_delta.xlsx
   - Brand new tenders discovered in the current run only.
   - Newness is determined by bid_number not already existing in the master file.
   - Filtered to the target category.

5. etenders_updates.xlsx
   - Existing tenders where selected operational fields have changed.
   - Changes are detected by comparing row_hash values.
   - Filtered to the target category.

6. etenders_top_delta.xlsx
   - Highest-scoring new tenders from the current run.
   - Built from the delta file only.
   - Sorted by weight_score descending, then closing_date ascending, then date_published ascending.

State and Lock Files
--------------------

- Used when the optional --stop-on-seen argument is applied.

- Prevents two scraper runs from executing at the same time.

Change Detection
----------------
The script creates a SHA256 row_hash using selected operational fields.

------------

Update Logic
------------
A tender is treated as UPDATED when:
- Its bid_number already exists in the master file, and
- The new row_hash differs from the previous row_hash in the master file.

A tender is treated as NEW when:
- Its bid_number does not exist in the master file.

Weight Scoring
--------------
The scraper applies a score to each clean record after the Services: Professional category filter.

Scoring Columns Added
---------------------
priority_client_match
matched_description_keywords
description_keyword_match_count
weight_score

Scoring Constants
-----------------
WEIGHT_CLIENT_MATCH = 10
WEIGHT_DESCRIPTION_KEYWORD = 1

Scoring Formula
---------------
weight_score =
(priority_client_match * 10) + (description_keyword_match_count * 1)

Top Delta Logic
---------------

- TOP_DELTA_MIN_SCORE_DEFAULT = 0

The top delta output is created from delta_df only.

Sorting:
1. weight_score descending
2. closing_date ascending
3. date_published ascending

If --top-delta-limit is set to 0, all qualifying delta rows are included.

Excel Formatting
----------------
Each Excel file is written using xlsxwriter.

When rows exist:
- The output is formatted as an Excel table.
- Header row is frozen.

When no rows exist:
- The workbook is still created with headers.
- An autofilter is applied.
- This confirms the script ran even when there were no qualifying rows.

Known Design Decisions
----------------------
1. Raw outputs are kept unfiltered.
   This preserves the full API response for audit and debugging.

2. Clean outputs are filtered to Services: Professional.
   This avoids downstream review of irrelevant categories.

3. The master is updated from all currently fetched Services: Professional rows.
   This allows newly introduced columns such as conditions and weight_score to be backfilled.

4. conditions is included in the hash.
   This means changes to tender conditions will trigger an update.

5. Description, category, client, and date_published are not used as hash fields.
   This keeps update detection focused on operationally important changes.

6. bid_number is lowercased.
   This keeps deduplication stable even where API formatting varies.

Recommended Daily Workflow
--------------------------
1. Run the scraper using --since-days 14.
2. Review etenders_top_delta.xlsx first.
3. Review etenders_delta.xlsx for all new professional services tenders.
4. Review etenders_updates.xlsx for changed tender details.
5. Use etenders_master.xlsx as the latest consolidated professional services tender register.
6. Use raw files only when checking whether a missing/odd tender was present in the API response.

Current Limitation
------------------
The scoring model is rule-based. It does not infer relevance beyond exact client matching and description keyword matching.

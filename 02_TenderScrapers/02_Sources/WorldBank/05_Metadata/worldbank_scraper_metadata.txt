Default fetch behaviour:
- Fetch mode: current
- Fetches the latest tail-window of World Bank procurement records.
- Default recent window: 20,000 records.
- Applies local filtering after fetch.
- Keeps notices where deadline_date is from today to today + 180 days.
- Excludes expired notices by default.

Reason for local filtering:
Testing showed that World Bank API field/date filters may be ignored for this dataset. To avoid pulling the full historical archive from 2005 onward, the script fetches a controlled latest-record window and filters locally.

Available fetch modes:
1. current
   Keeps currently open notices based on deadline_date.

2. recent
   Keeps notices based on recent publication_date.
   Controlled by --since-days or --since-date.

3. all
   Pulls the full archive.
   Use sparingly because the dataset is large.

Opportunity key logic:
- Prefer official World Bank notice ID.
- Prefix with worldbank:.
- If no notice ID is available, use a stable fallback composite of project_id, bid_description, publication_date, and deadline_date.

Master logic:
- Maintains the latest cleaned snapshot per opportunity_key.
- Deduplicates by opportunity_key.
- Updates master using all currently fetched and cleaned records, not only delta/update records.

Delta logic:
- Delta contains records found in the current run that do not already exist in the master file.
- change_type is set to NEW.

Updates logic:
- Updates contains existing records where the row hash has changed.
- change_type is set to UPDATED.
- previous_row_hash is included for comparison/audit purposes.

Hash/change detection fields:
- bid_description
- deadline_date
- notice_type
- procurement_category
- procurement_method
- sector
- url

Top delta logic:
- Based only on delta records.
- Sorts by weight_score descending.
- Secondary sorting uses deadline_date and publication_date where available.
- Default top list limit: 20 records.
- Default minimum score: 0.

Notes and limitations:
- The official structured dataset appears to expose only the listed API fields.
- Additional detail may be available from each notice URL, but that would require a second-stage notice-page scraper.
- The current script does not scrape detail pages.
- If the recent tail-window is too small, some current notices could be missed if they sit outside the latest fetched records.
- If the recent tail-window is too large, the run will be slower but more complete.
- Recommended starting point is 20,000 records, adjusted after observing daily output volume.

Operational recommendation:
Use the World Bank scraper as a separate source-specific pipeline. Once eTenders, World Bank, and future scrapers are stable, create a separate consolidation script that reads each portal's master/delta/top_delta files and compiles a combined opportunity register with standard columns.
